# FAQ Defence — OpsFlow (WebMCP Challenge — Top 10)

> Generated for DP-PITCH W4. Contains 4 mandatory answers verbatim from DP-PITCH §5.4.1 plus 8 domain questions to satisfy >=12 total.

### Why couldn't this be built before WebMCP?

Before WebMCP, agents could only scrape DOM selectors — brittle, hallucinated, and N-step guesswork per filter. OpsFlow's batch needs constraint-preserving co-execution (`search_inventory → filter_variants → calculate_shipping → hold_order → confirm_fulfillment`) with typed I/O. The page now declares five tools with `document.modelContext.registerTool({ name, description, inputSchema, execute })`, JSON Schema, and annotations; the agent knows exactly how to call them in 2–3 deterministic steps with validation. WebMCP (Draft 2026-08-26, Chrome 149 origin trial + ChatGPT in-app browser) made declared `execute` callbacks — instead of DOM scraping — possible for the first time.

### What stops the agent doing something destructive?

Every state-changing tool (`hold_order`, `confirm_fulfillment`) stops at a focus-trapped confirmation dialog showing the exact validated arguments (`FR-05`, `FR-06`). `runTool` never throws — failures resolve as typed `ToolError`s — and `options.signal` abort resolves `TOOL_ABORTED` with no partial state. The orchestrator goes through `document.modelContext.executeTool`, the same entry point an external agent uses, so the gate cannot be bypassed. No hold commits without a human click.

### What happens with a browser that has no WebMCP?

The page calls `probeWebMcp()` on load. If unavailable, a full-width banner states "WebMCP not detected" with both enablement paths (ChatGPT in-app browser, or Chrome 149+ with `chrome://flags/#enable-webmcp-testing` + restart) and notes the in-page Agent Console still runs the full flow via `executeToolCompat` → `runTool` direct (ladder rung 4). The Tool Inspector shows the schema fallback with "not registered — showing schema fallback". No functionality is lost; only the external-agent entry point is absent.

### Is the data real?

No — all 200 SKUs, zone tables, and baselines are synthetic, every record carries `synthetic: true`, and the UI shows a persistent "synthetic data" badge (`NFR-04`). `data/catalog.json` is generated by `DP-SEED` via `generateRecords` with watermark headers. The demo is honest: the savings claim (25 min → ~3 min) is measured as a visible meter comparing `baseline_minutes`/`baseline_clicks` from `data/baseline.json` against `tool_calls`/`confirmations`/`elapsed_ms` of the current batch, demonstrated rather than asserted.

### How long does a hold last and what happens when it expires?

`hold_order` takes `ttlMinutes` per the tool schema; the demo goal uses 15 minutes as an example but any validated TTL is accepted. Holds are reversible and tracked in the Holds screen; when the TTL expires stock is released, no order is cancelled and no partial state remains because `runTool` never throws — expiry is a typed outcome, not an exception.

### What does calculate_shipping's explain[] contain?

`calculate_shipping({ items, zone, service })` returns a `quote` plus an `explain[]` array that narrates every rule applied: base rate per zone from `data/zones.json`, surcharges, and which variants were excluded with reasons. The Shipping card renders `explain[]` so Maya and the agent see why a variant was excluded, not just the total.

### How does filter_variants preserve constraints across steps?

`filter_variants({ skuPrefix, options, maxPrice })` narrows the *current* result set from the preceding `search_inventory`, keeping constraint context. The agent chains `search → filter → calculate` in deterministic steps, validating inputs against JSON Schema before execution, so no filter loses prior constraints.

### What is the single track for this entry and is there a bonus integration?

Track: WebMCP Challenge — Top 10. No bonus integration — not worth dilution. The entry names only that track in deck slide 1 and submission.md, with no sponsor sub-challenge or bonus module, consistent with MAN-10.

### How many tools and screens does the app expose?

Five imperative WebMCP tools registered from the single call site `src/webmcp/register.ts` (`search_inventory`, `filter_variants`, `calculate_shipping`, `hold_order`, `confirm_fulfillment`) plus one declarative form for `calculate_shipping` in `ShippingScreen.tsx`. Three screens: Batch, Shipping, Holds. No sixth tool, no fourth screen.

### How is origin isolation enforced?

The Vercel deploy sends `Origin-Agent-Cluster: ?1` and `Permissions-Policy: tools=(self)` (MAN-03). No cross-origin iframe is shipped; if a cross-origin iframe were added it would need `allow="tools"`. This is verifiable via headers and `probeWebMcp()`.

### How is synthetic data watermarked and disclosed?

All 200 SKUs in `data/catalog.json` carry `synthetic: true`; `data/baseline.json` carries `synthetic: true` with `baseline_minutes: 25` and `baseline_clicks: 120`. The UI shows a persistent synthetic data badge per NFR-04 and `disclosure.md` lists reused chassis components.

### What happens when Gemini is unavailable or the network fails?

The server path `POST /api/agent/plan` is wrapped with `withResilience` and the demo uses golden cache replay from `.cache/golden/` (DP-CORE/DP-SEED). When the key or network is absent the deterministic keyword planner maps intent to `ToolPlan` and replay shows cached outputs with a degraded chip, so the demo never shows a blank screen.
